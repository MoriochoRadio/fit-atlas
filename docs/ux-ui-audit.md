# Fit Atlas UX·UI 개선 점검

## 2026-08-21 · 1차 핵심 흐름 점검

홈·세션·운동 탐색·바디 맵·기록 분석·웰니스의 데스크톱 화면과 세션·운동 탐색의 390px 모바일 화면을 확인했다. 전체 제품은 딥 잉크·웜 화이트·전기 라임의 신호 체계와 큰 한글 제목, 교육 중심의 차분한 문체가 일관되게 유지된다. 다만 모바일에서는 세션 시작 선택지가 세로로 길고, 운동 탐색 상단의 ROM 제어가 지나치게 많은 세로 공간을 차지해 핵심 카드 진입이 늦어지는 문제가 있었다.

이번 개선에서는 기능이나 데이터 구조를 바꾸지 않고, 모바일 세션 빠른 시작을 한 줄 요약형 선택 행으로 압축했다. 운동 탐색 ROM 제어는 가로로 훑을 수 있는 버튼 행으로 바꾸고, 현재 ROM 상태 카드의 넓은 터치 행동은 유지했다. 두 장면 모두 고정 빠른 이동 바와 함께 확인했으며, 첫 화면에서 세션의 세 시작점과 탐색의 ROM 선택·권장 행동이 더 빠르게 노출된다.

다음 점검은 세션 계획 본문의 정보 밀도, 운동 카드의 스캔성, 바디 맵 관련 운동 목록의 터치 우선순위를 대상으로 한다.

## 2026-08-21 · 2차 세션 설계 점검

세션 설계의 첫 화면에서는 세 가지 빠른 시작 선택지가 현재 조건보다 먼저 보이고, 목표·환경·시간의 세부 조정은 그 다음에 배치되어 있다. 다만 계획 카드의 본문은 단계별 구획보다 목록 문장이 먼저 눈에 들어와, 사용자가 준비·주요 움직임·마무리의 순서와 각 단계의 시간을 빠르게 훑기 어려웠다.

계획 블록을 단계 번호, 단계명·시간, 핵심 동작 카드로 다시 나누고 실행 행동과 안전 안내를 별도의 하단 구획으로 정리했다. 390px 모바일에서는 세 블록을 수직 코칭 카드로 전환해 줄 길이와 터치 영역을 유지한다. 이후 단계에서는 긴 동작 설명을 운동 상세에서 확인할 수 있도록 요약 단서와 전체 설명의 노출 우선순위를 더 보정한다.

## 2026-08-21 · 3차 운동 탐색 점검

운동 탐색은 빠른 시작, 검색·필터, 저장한 조건, 최근 본 운동, 카드 목록의 순서로 구성되어 있다. 핵심 탐색 기능은 유지하되 카드 영역에서는 카테고리·난이도·시간·장비와 상세 진입 행동이 같은 밀도로 섞여 있어 빠른 비교가 어려웠다.

카드 상단에 일관된 신호 점과 난이도 레이블을 두고, 시간·장비 메타를 분리된 짧은 정보 행으로 보강했다. 설명은 두 줄을 넘기지 않도록 제한하고, 상세 진입 행동은 카드 폭 전체를 쓰는 명확한 버튼으로 바꿨다. 모바일에서는 이 행동의 터치 높이를 늘려 목록 스크롤 중에도 다음 행동을 빠르게 찾도록 했다. 다음 점검에서는 실제 카드 구간의 모바일 전체 화면과 필터·상세·페이지 추가 흐름을 함께 검증한다.

## 2026-08-21 · 4차 바디 맵 점검

바디 맵은 인체 모델과 텍스트 부위 선택을 함께 제공하고, 선택한 부위에 연관된 운동을 오른쪽 목록으로 연결한다. 기존 목록은 항목을 읽고 눌러야 한다는 사실이 충분히 드러나지 않았고, 선택 부위와 관련 운동의 관계도 한 번 더 해석해야 했다.

선택 부위 영역에 `SELECTED` 신호와 지도형 상단 선을 추가하고, 부위 버튼·관련 운동 항목을 명확한 터치 행으로 정리했다. 목록에는 카테고리 신호, 개수 배지, 이동 화살표를 두어 선택한 근육에서 다음 운동 상세로 이어지는 경로를 선명하게 만들었다. 모바일에서는 관련 운동 행의 최소 높이와 선택 버튼의 크기를 높여 모델 조작 뒤의 다음 행동을 놓치지 않도록 했다.

## 2026-08-21 · 5차 기록 분석 점검

기록 분석 화면은 주간 ROM·완료 흐름, 요약 지표, 부하·일관성·부위 균형, 유산소·추세, 주간·월간 차트, 개인 기록과 날짜별 기록을 함께 제공한다. 다만 기록이 적을 때 여러 카드의 무게가 비슷해 현재 핵심 신호와 다음 기록 행동이 충분히 앞서지 않았다.

이번 보정에서는 주간 흐름과 부하 카드를 분석의 중심 표면으로 강화하고, 보조 지표·추세·차트는 더 가벼운 위계로 정리했다. 빈 차트는 점선 경계와 첫 기록 행동이 분명한 전용 상태로 만들고, 모바일에서는 요약 카드와 다음 행동이 한 열로 자연스럽게 이어지도록 구성했다.

## 2026-08-21 · 6차 웰니스 점검

웰니스 장면은 회복 시작, 생활 습관, 유산소, 무점프, 안전 정보를 긴 문서 안에 함께 제공한다. 내용이 풍부한 만큼 현재 위치와 회복 시작 행동을 잃기 쉽고, 안전 경계는 행동 카드와 구분되어야 한다.

목차를 스크롤 중에도 유지되는 가로 경로 바로 정리하고, 현재 섹션에는 라임 신호를 적용했다. 회복 시작 카드에는 시간 선택·저장 행동·완료 기록을 하나의 짧은 경로로 묶고, 조절 안내와 중단 신호는 별도 경계로 강조했다. 모바일에서는 목차를 가로 스크롤로 전환해 문서 폭을 유지하면서도 다음 섹션 이동을 잃지 않도록 했다.

## 2026-08-21 · 7차 공통 상태·탐색 점검

독립 장면 전환은 잘 작동하지만, 모바일 빠른 이동에서는 현재 장면과 기록 행동의 구분이 충분히 강해야 한다. 또한 키보드 사용자는 현재 초점의 위치를 놓치지 않아야 하고, 브라우저 저장이 제한되는 경우에는 화면이 유지되는지와 다음 조치를 분명히 알아야 한다.

현재 장면에 대응하는 모바일 빠른 이동 항목을 라임 신호로 강조하고, 상단 탐색의 현재 페이지 신호와 함께 일관된 상태 언어를 적용했다. 버튼·링크·입력 필드에는 장면 색을 따르는 포커스 링을 제공하며, 저장 제한 안내는 고정 경고 표면으로 분리해 모바일 하단 탐색과 겹치지 않도록 배치했다.

## 2026-08-21 · 8차 시작·세션 계획 점검

홈의 빠른 시작은 목적을 고르는 데 충분히 명확하지만, 세션 계획의 세 단계는 주된 움직임 목록이 길어질 때 준비·마무리 단계까지 같은 높이로 보이며 읽기 리듬을 늦출 수 있다. 이는 처음 계획을 실행하려는 사용자에게 필요한 단계보다 빈 표면을 먼저 보게 하는 문제다.

세션 단계 카드는 서로 독립적인 높이를 유지하도록 정렬 규칙을 보정하고, 주된 움직임에는 라임 신호, 마무리에는 보조 색을 사용해 단계 역할을 구분했다. 하단 실행 행동도 경로 선으로 분리해 계획을 읽은 뒤 저장·기록으로 이어지는 다음 행동을 명확히 했다.

## 2026-08-21 · 9차 반복 방문 시작 흐름 점검

반복 사용자는 이미 장비·저항을 정한 최근 세션이 있어도 홈의 기본 `오늘 세션` 행동을 다시 거쳐야 했다. 최근 설정 카드는 보조 위치에 있었으므로, 가장 먼저 보이는 행동이 현재 사용 맥락을 이어 주지 못할 수 있다.

최근 장비 세션이 저장된 경우 홈의 주 행동을 `최근 세션 이어하기`로 전환해 동일한 장비·저항·목표 기준을 세션 설계에 바로 복원하도록 했다. 저장된 세션이 없는 첫 방문에서는 기존 `오늘 세션` 진입을 유지해 두 사용자 상태의 시작 경로를 분리했다.

## 2026-08-21 · 10차 운동 상세 읽기 흐름 점검

운동 카드는 요약 정보가 충분히 간결했지만, 상세를 열면 이점·자세 지도·설정·폼 단서·변형·주의·근거가 하나의 긴 연속 문서로 읽힐 수 있었다. 특히 모바일에서는 상세 내용을 따라가며 안전·근거 경계를 다시 찾기 어렵다.

상세 표면을 연한 지도형 배경으로 묶고, 이점·설정·폼 단서·흔한 오류를 라임 경계로 구분했다. 읽으며 따라 하는 자세 지도는 별도의 요약 패널로 올리고, 주의 신호와 근거 적용 범위는 독립 표면으로 분리했다. 상세 열기·닫기 행동도 50px 모바일 터치 영역으로 보강했다.

## 2026-08-21 · 11차 운동 탐색 필터 흐름 점검

운동 탐색은 빠른 시작과 종류 선택 뒤 검색·상세 조건·정렬·프리셋·목록을 제공하지만, 정렬은 상세 조건을 열어야 확인할 수 있고 적용한 조건·현재 표시 수·빈 결과의 다음 행동은 서로 떨어져 있었다. 초보 사용자는 조건을 더해야 할지, 초기화해야 할지 판단하기 위해 여러 표면을 오갈 수 있었다.

정렬을 검색 바로 아래의 우선 제어로 올리고, 상세 필터는 기본 경로에서는 계속 접어 두되 적용 조건 수를 알려 주도록 정리했다. 결과 요약은 일치 수·현재 표시 수·불러온 카탈로그 범위·적용 조건을 한 표면으로 묶었고, 빈 결과에서는 이유와 전체 조건 초기화 행동을 함께 제공했다. 데스크톱과 390px 모바일 전체 화면에서 정렬·상세 조건·결과 요약·목록의 흐름을 확인했다.

## 2026-08-21 · 12차 운동 카드·목록 가독성 점검

운동 카드에는 이미 카테고리·난이도·설명·태그·시간·장비·상세 보기 행동이 있었지만, 시간과 장비의 값이 같은 행에서 바로 읽혀 비교 단위가 약하고, 긴 설명은 메타와 상세 진입 사이의 리듬을 흐릴 수 있었다. 상세 보기의 열림 상태도 시각적 변화 외에는 보조기기에 직접 전달되지 않았다.

카테고리는 신호 점이 있는 짧은 라벨로, 난이도는 독립 배지로 정리했다. 설명은 안정적인 두 줄 리듬을 유지하고, 시간·장비는 레이블과 값이 분리된 두 칸 메타로 다시 구성했다. 상세 보기에는 확장 상태와 상세 영역 연결을 제공했으며, 390px 모바일에서는 설명 줄 길이와 52px 상세 진입 터치 영역을 확인했다. 카드 요약은 지연 로드해 Home 초기 청크도 500kB 미만으로 유지했다.

## 2026-08-21 · 13차 색상 대비 사전 점검

홈·세션·운동 탐색·바디 맵·기록 분석·웰니스의 데스크톱 화면을 비교했다. 딥 잉크 제목과 라임 주 행동은 충분히 구분되지만, 웜 화이트 배경 위의 회색 보조 문장·미세 레이블·약한 올리브 링크, 그리고 카드 안의 시간·장비 메타 일부는 화면 축소 또는 밝은 주변광에서 빠르게 읽기 어려울 수 있었다. 밝은 상태 표면에서 낮은 대비의 보조색이 반복되는 것도 정보 위계를 흐리게 한다.

이번 보정은 라임을 읽기용 본문 색으로 쓰지 않고 행동·선택 신호로만 유지하며, 보조 텍스트와 메타는 더 짙은 청회색으로, 기술 레이블·올리브 링크는 더 깊은 녹갈색으로 통일하는 방향을 기준으로 한다. 안전·경고 표면은 기존의 별도 색 체계를 유지하되 본문 색 대비를 함께 높인다.

대비 토큰을 적용한 뒤 탐색과 웰니스의 데스크톱·390px 모바일 화면을 재확인했다. 본문과 보조 설명은 웜 화이트 표면에서도 명확히 분리되고, ROM 안내·필터·상태 표면의 행동 신호는 라임을 유지하면서도 설명 텍스트와 경쟁하지 않는다. 모바일에서 긴 제목·설명은 자연스럽게 여러 줄로 이어지며, 고정 빠른 이동 바와 겹치는 텍스트는 확인되지 않았다. 키보드 포커스는 3px 올리브 외곽선과 라임 링을 함께 사용해 밝은 표면에서도 위치를 파악할 수 있게 했다.
