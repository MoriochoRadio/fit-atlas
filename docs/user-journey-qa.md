# Fit Atlas 사용자 여정 QA 기준

## 점검 원칙

이 QA는 기능이 렌더링되는지만 확인하지 않는다. 사용자가 **무엇을 할 수 있는지 즉시 이해하는지**, 행동 뒤에 **예상 가능한 결과와 피드백을 받는지**, 작은 화면과 키보드에서도 **막히지 않는지**를 확인한다. 모든 로컬 저장 동작은 새로고침과 다시 접속한 뒤에도 의도한 상태를 복원해야 하며, 직접 URL과 브라우저 앞뒤 이동은 사용자의 명시적 위치 선택을 우선한다.

| 여정 | 실제 사용자 행동 | 합격 기준 |
|---|---|---|
| 첫 방문 | 홈에서 오늘 세션 또는 운동 탐색을 선택 | 첫 화면에서 두 행동의 의미와 다음 화면이 명확하고, 이동 뒤에는 이전 장면 콘텐츠가 남지 않는다. |
| 장비 기반 시작 | 기구 선택·저항 조절·세션 설계 실행 | 선택값과 강도 안내가 즉시 바뀌며, 세션 화면에도 같은 목표가 유지된다. |
| 운동 탐색 | 빠른 카테고리·검색·상세 조건·프리셋 사용 | 필터 상태가 결과와 일치하고, 저장·적용·삭제가 어떤 조건을 바꾸는지 읽을 수 있다. |
| 바디 맵 | 부위 선택·다중 선택·관련 운동 진입 | 선택 상태와 운동 목록이 서로 일치하며, 상세로 넘어가도 탐색 경로를 잃지 않는다. |
| 기록과 회복 | 체크인·기록 입력·회복 동선 | 보수적 안내와 저장 결과가 분명하고, 위험 신호는 일반 안내의 범위를 넘지 않는다. |
| 반복 방문 | 마지막 장면·최근 장비·프리셋 복원 | 해시 직접 링크를 우선하고, 해시가 없을 때만 마지막 장면을 복원한다. |
| 모바일·키보드 | 메뉴·장면 설정·모달 열기·닫기 | 메뉴가 확실히 보이고, 탭·Esc·포커스 이동으로도 주요 행동을 끝낼 수 있다. |

## 검증 방식

데스크톱과 390px 모바일에서 각 장면의 첫 화면, 행동 후 화면, 모달·메뉴 상태를 시각 확인한다. 이어서 통합 회귀에서 장면 이동, 브라우저 이력, 로컬 복원, 프리셋, 장비 시작을 검증하고, 타입 검사와 정적 빌드로 배포 가능한 상태를 확인한다.

## 2026-08-20 사용자 관점 점검 결과

| 장면·흐름 | 관찰 결과 | 조치 및 상태 |
|---|---|---|
| 홈과 장비 시작 | 오늘의 강도·장비·세션 설계 행동이 첫 화면에 함께 보이며, 주간 정보는 보조 위계로 내려가 있다. | 통과. 장비 선택과 저항은 세션 설계·RPE 안내로 이어짐을 통합 회귀로 확인했다. |
| 세션 설계 | 빠른 시작, 조건 선택, 계획 저장, 기록 진입의 순서는 일관되지만 설명이 긴 화면에서는 작은 보조 텍스트가 누적된다. | 핵심 CTA를 상단·계획 카드·하단에 유지하고, 모바일 보조 본문의 줄 간격을 보강했다. |
| 운동 탐색 | 검색·빠른 필터·상세 필터·프리셋·최근 항목이 모두 있어 카드의 텍스트 대비가 특히 중요하다. | 카드 배경·제목·설명·메타·행동 텍스트의 색 대비를 명시했고 모바일 카드 본문·메타 글자 크기를 보강했다. |
| 바디 맵 | 모델·부위 목록·관련 운동의 연결은 명확하나 작은 화면에서 관련 운동의 조작 대상이 충분히 커야 한다. | 정보 패널의 글자색을 명시하고 관련 운동 행을 최소 48px로 확장했다. |
| 기록과 웰니스 | 비어 있는 기록 상태와 안전 안내가 구분되며, 긴 회복·웰니스 문서는 작은 화면에서 더 여유 있는 본문이 필요했다. | 모바일 본문 줄 간격과 고정 하단 탐색을 고려한 푸터 여백을 보강했다. |
| 모바일 메뉴·설정 | 메뉴·설정 진입, 모바일 빠른 탐색, Esc로 모달 닫기, 최근 장면 복원, 브라우저 앞뒤 이동을 점검했다. | 메뉴와 장면 설정 경로, popstate 동기화, 설정 모달·메뉴 닫힘을 자동 회귀로 고정했다. |
